# FlowTrace — Backlog v2: Business Flows ("Live Shop" extension)

> **New tasks only.** This file does not repeat or replace anything in `TASKS.md` (v1). Read v1 sections 0–2 first: the agent workflow, conventions, size/priority scale and the Global Definition of Done apply here unchanged.
> **IDs continue from v1:** epics `E17–E25`, human tasks `H-11+`, decisions `DEC-11+`.
> **Idea:** a token stops being an anonymous dot. It becomes an **entity** (a visitor/customer icon) that **carries** things (cart items with their icons) through **business steps** (visit → cart → checkout → paid). Ready-made **templates** for typical small businesses. Target user: a non-technical owner of a small business.
> **Principle:** validation-first. Build the "Shop Demo" slice first, connectors only after the market gives a signal (see gates).

## 4. Event schema extension (v1.1, backward compatible)

```json
{
  "v": 1,
  "traceId": "0194f1c0-7b52-7c1e-9a3e-5f0d2b6c8a11",
  "node": "cart",
  "type": "enter",
  "entity": { "kind": "customer", "ref": "c-1042", "label": "Visitor", "avatar": "fox" },
  "carry": {
    "op": "add",
    "items": [
      { "sku": "candle-lavender", "label": "Lavender candle", "icon": "emoji:🕯️",
        "image": "https://shop.example/img/candle.jpg", "qty": 1, "price": 12.50, "currency": "EUR" }
    ]
  },
  "attrs": { "campaign": "autumn" }
}
```

Rules (normative; mirror them in `PROTOCOL.md`):
- `entity` is optional. Without it the `traceId` is the entity and the UI keeps the classic dot. `ref` is an opaque client id: the server stores only a **project-salted hash** (E23-01).
- `carry.op` ∈ `set | add | remove | clear`. The server keeps `carry` state per trace (inside `TraceState`) and sends the resulting summary to the UI. Limits: ≤ 20 items per event, ≤ 50 per trace, `label` ≤ 60 chars, `icon` ≤ 200 chars. Totals are computed server-side.
- `icon` is `emoji:<char>`, `lib:<key>` (built-in library) or omitted. `image` must go through the proxy (E17-06), never loaded directly by the browser.
- New `type` values: `complete` (success end), `fail` (failure end), `abandon` (normally generated by the server on idle policy, E17-07).
- New UI stream messages: `carry` (change without move), `abandon`, `complete`, `fail`, `crowd` (aggregated count); `hop` messages gain an optional `carry` summary `{count, total, currency, top:[icons]}`.
- v1 clients are unaffected. Unknown fields are ignored. Bump the protocol doc version.

## 5. Template format

```
templates/<id>/template.json
{
  "id": "online-shop", "name": "Online shop", "category": "commerce", "version": 1,
  "diagram": { /* graph JSON: nodes with icons, zones/lanes, edges */ },
  "theme": "cozy-light",
  "entityKinds": [ { "kind": "customer", "avatars": "animals" } ],
  "terminalNodes": { "success": ["paid"], "failure": ["payment-failed"], "abandon": ["abandoned"] },
  "simulator": { "scenario": "online-shop.yaml", "defaultRate": 0.5 },
  "connectors": ["js-snippet", "stripe", "webhook"],
  "kpis": [ { "id": "conversion", "from": "visit", "to": "paid" } ]
}
```
Templates are **data only** (no code). They are validated against a JSON Schema.

## 6. Epics and tasks

### E17 — Entity tokens & carried payloads (core engine)
- [ ] **E17-01** ⚠ (P0, M) Event schema v1.1 (`entity`, `carry`, new types) — AC: JSON Schema + `PROTOCOL.md` updated; v1 payloads still accepted; golden vectors (E7-06) extended; rules from section 4 enforced.
- [ ] **E17-02** (P0, M) Server-side carry state in `TraceState` — AC: ops `set/add/remove/clear`, totals, limits; unit tests for every op and limit; same TTL as the trace.
- [ ] **E17-03** (P0, M) UI stream extension (`carry`, `abandon`, `complete`, `fail`, `crowd`); snapshot includes active entities with carry — AC: backward compatible; WS integration test.
- [ ] **E17-04** (P0, L) Entity token renderer — AC: token = avatar/icon (not a dot) with a count badge and up to 3 mini item icons following it; moves along edges with the existing animation engine; falls back to the dot when `entity` is missing; 100 entities with carry hold 60 fps.
- [ ] **E17-05** (P0, M) Carry animations — AC: pickup (item flies from the node to the token), drop-in at terminal nodes (items "go into" Payment), running total shown on the node; deterministic; reduced-motion variant.
- [ ] **E17-06** ⚠ (P0, M) Item icon pipeline + **image proxy** — AC: sources `emoji:`, `lib:` or image URL; proxy with domain allowlist, size cap (≤ 200 KB), content-type check, SVG sanitization, SSRF protection, CDN cache; fallback to a library icon by category; security tests for SSRF, oversized and malicious SVG.
- [ ] **E17-07** (P1, M) Idle/abandon policy per node (e.g. idle > N min at `checkout` → synthetic `abandon`) — AC: server-side timers recoverable after restart (recomputed from `TraceState`/persisted deadlines); token fades with a "left" animation; tested.
- [ ] **E17-08** (P1, M) Terminal semantics `complete / fail / abandon` mapped to node roles (success / failure / abandon) with distinct effects and counters — AC: configurable per template.
- [ ] **E17-09** (P1, L) **Crowd mode** — AC: above a configurable number of entities at a node, low-intent entities collapse into a count + pulse while entities carrying items stay individual; UI holds 60 fps at 2,000 events/s; "crowd/sampling" chip visible; thresholds configurable.
- [ ] **E17-10** (P2, M) Link two traces by `entity.ref` (anonymous visitor → logged-in customer) — AC: merge rules documented; token continuity in the UI.
