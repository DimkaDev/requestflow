# ADR-0004: Auth, ID Format & AWS Infrastructure

- **Status:** Accepted
- **Date:** 2026-11-07

## Context
We need an authentication mechanism that supports Amazon Cognito OIDC in production and frictionless local development without AWS credentials, a time-sortable UUID format for traces, and reproducible AWS Infrastructure-as-Code.

## Decision
1. **ID Format:** UUIDv7 (time-ordered RFC 9562 UUID) generated by default in `client-java` and `POST /api/v1/traces`. Ingest accepts any valid UUID string (`v1`–`v8`).
2. **Authentication:**
   - UI/Management API (`/api/v1/projects/**`): OIDC Bearer JWT in `prod` (Amazon Cognito User Pool with Authorization Code + PKCE); in `dev`/`test` profiles (`flowtrace.auth.mock-enabled=true`), a built-in mock OIDC/JWT filter defaults unauthenticated or dev-token requests to a seeded local developer user (`dev@flowtrace.local`) while still supporting custom `X-Debug-User-Id` headers for multi-tenant isolation tests.
   - Ingest API: Write-only API keys (`ft_live_<32 chars>`), stored as `key_prefix` + `SHA-256(key)`, cached in Caffeine for 60s with immediate eviction on revocation.
3. **IaC Tool:** AWS CDK in Java (`infra/` module, `aws-cdk-lib` `2.275.0`), organized into `NetworkStack`, `DataStack`, `AuthStack`, `BackendStack` (ALB for HTTPS/WS + NLB for TCP 9000 / UDP 9001 → single Fargate task), and `FrontendStack` (S3 + CloudFront OAC), targeting `eu-west-1` by default.

## Consequences
- Local `docker compose up` and automated integration tests work out-of-the-box without an AWS account.
- Multi-tenant isolation is strictly enforced and testable via distinct user identities.
